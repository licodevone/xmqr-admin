# XMQR Admin 0.11.0 — compatibilidade com estado v16

Marco experimental A22 publicado na [prerelease0.11.0](https://github.com/licodevone/xmqr-admin/releases/tag/v0.11.0),
fonte4483a356196db93f99340bc7aa3b3cabfc4af810. CI exata, pacote, ciclos
descartáveis, imagem por digest e14anexos remotos verificados. Não encerra
a fase6 global. [Evidência de distribuição](../evidence/admin-a22-release-0.11.0.json).

O core Git imutável é broker0.43.0,
`ba6ef50204dec2c6385b272e595260b9def1e794`. A21 validou backup/verify/restore
offline de retained, offlineQoS1 e Will pendente, conservando bytes, hashes,
watermark e intervalo original de expiração. Estado15 produzido por binário
legado real migra para16 sem inventar intervalo original ausente. Negativos
de lock/estado ativo/corrupção/symlink/destino existente preservam os dados.

Faça backup privado com broker parado antes da primeira gravação16. O
broker042/estado15 recusa16; rollback executável exige backup15 anterior,
não apenas reinstalar o executável. Admin010 pode transportar backup bruto,
mas isso não o torna o par homologado de execução do formato novo.

CLI e painel preservam seus contratos. Painel é observador de leitura local,
sem CRUD por HTTP, sem exposição remota/0.0.0.0 e sem serviços automáticos.
`xmqr-admin` não substitui o `mqtt-admin` legado, o broker ou o client.

MIT própria e textos originais das dependências são distribuídos em notices;
não há relicenciamento do conjunto. `.deb` e tar são Ubuntu26.04 amd64;
Docker é build separado DebianBookworm linux/amd64, UID/GID10001:10001.
Sem homologação Windows nativo, arm64, produção, energia ou conformidade
MQTT5 integral. [Registro A22](../../prompts/registros/A22-release-0.11.0.md).
